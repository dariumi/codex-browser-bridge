# Установка, подключение и проверка

[English guide](INSTALL.md) · [Инструкция агенту](AGENT_SETUP.md) · [README](../README.ru.md)

Нужны **две части**: локальный Node.js-мост на компьютере Codex и расширение в браузере. Они соединяются одним приватным файлом настроек. Одного установленного расширения недостаточно для появления инструментов MCP.

## 1. Подготовьте компьютер

Установите Git, Node.js 22+ и [Codex CLI](https://learn.chatgpt.com/docs/cli). В терминале проверьте:

```bash
git --version
node --version
npm --version
codex --version
codex login
```

Вход в Codex нужен для чата расширения. Другой MCP-клиент может использовать инструменты браузера отдельно от этого чата.

## 2. Установите мост и зарегистрируйте MCP

```bash
git clone https://github.com/dariumi/codex-browser-bridge.git
cd codex-browser-bridge
npm ci
npm run setup
npm run package
```

Для автоматического обновления нужен Git clone. Исходники из ZIP работают, но не могут обновляться через Git.

Setup создаёт `.local/connection.json`, регистрирует `browser_bridge` в Codex и запускает мост. В конце выводятся точные пути папок и файла подключения без самого ключа. Не переносите папку проекта без повторного запуска setup.

Настраиваются абсолютные пути Node и MCP, startup timeout 10 секунд, tool timeout 900 секунд для проверки обновлений и `required = true`. Общая политика подтверждений Codex не меняется.

Если хотите делегировать браузерные действия из обычных разговоров Codex без отдельного подтверждения каждого вызова MCP, выберите явно:

```bash
npm run setup -- --delegate-browser
```

Это устанавливает `default_tools_approval_mode = "approve"` **только для browser_bridge**. Правила сайтов и разрешения JavaScript/CDP остаются в силе. Встроенный чат уже настраивает делегирование для своего авторизованного задания.

Без Codex CLI: `npm run setup -- --no-codex`, затем ручная настройка MCP-клиента. При первой установке `--port 17865` выбирает другой порт; `BROWSER_BRIDGE_CONFIG` задаёт другой путь файла. В расширение должен быть импортирован именно соответствующий файл.

## 3. Загрузите расширение

### Chrome / Chromium / Brave / Edge

1. Откройте `chrome://extensions`, `brave://extensions` или `edge://extensions`.
2. Включите **Режим разработчика**.
3. Нажмите **Загрузить распакованное расширение** и выберите папку `extension` проекта, не manifest и не ZIP.
4. Через значок расширения откройте **Настройки**.
5. Импортируйте `.local/connection.json`. В Linux Ctrl+H показывает скрытые папки; на других системах используйте полный путь из вывода setup.
6. Дождитесь статуса **Подключено**.

### Firefox Desktop 142+

1. Выполните `npm run package` для сборки дополнения.
2. Откройте `about:debugging#/runtime/this-firefox`.
3. Нажмите **Загрузить временное дополнение**, выберите `dist/firefox/manifest.json`.
4. Откройте настройки дополнения, например через `about:addons` → Codex Browser Bridge → Параметры.
5. Импортируйте тот же `.local/connection.json` и дождитесь подключения.
6. Откройте **сам сайт, с которым хотите работать**, в другой вкладке. `about:debugging` и `about:addons` нужны для установки, агент не может выполнять задания на них.

После перезапуска Firefox временное дополнение загружается повторно. Постоянная установка требует подписи Mozilla; подписанный XPI пока не выпускается. Chromium manifest для Firefox не подходит.

К одному мосту подключается один браузер. Перед переключением отключите расширение в другом браузере.

## 4. Подключите Codex и проверьте всю цепочку

После регистрации перезагрузите MCP в Codex или начните новую сессию: уже открытый разговор может хранить старый список инструментов.

```bash
codex mcp get browser_bridge
npm run doctor
```

Doctor проверяет Node, вход Codex, регистрацию и пути MCP, файл подключения, версии моста/расширения, **настоящий stdio MCP handshake**, инструменты и сетевую защиту. Ключ и личные идентификаторы аккаунта не выводятся. Для агента: `npm run doctor -- --json`. Исправьте все строки `FIX`, пока проверки не покажут `OK`.

Затем попросите Codex: «Используй browser_bridge, проверь browser_status, выведи browser_tabs и изучи выбранную мной вкладку». Обычная HTTP(S)-вкладка должна быть доступна; данные защищённой вкладки скрыты до вашего разрешения.

Для встроенного чата откройте сайт, нажмите **Чат Codex**, проверьте заголовок и URL цели. Если выбран экран установки, перейдите на сайт и нажмите **Использовать открытую вкладку**. Для начала отправьте небольшую задачу, например изучить страницу без изменений.

Когда появляется карточка доступа, **вы** выбираете «Разрешить» или «Отказать» в чате, popup или настройках. Агент не может выдать разрешение себе. Доступ ограничен по времени, отказ обходить нельзя.

## 5. Длительная автономная работа

Включите **Выполнить все этапы самостоятельно** и **Длительная работа с ожиданием и пробуждением**. Выберите срок задачи 1–72 часа, по умолчанию 24. Доступны до четырёх часов активной работы и 200 ходов. Обычный режим сохраняет лимит 30 минут / 20 ходов.

Опишите условие ожидания и что проверить после него. Агент вызывает `browser_task` → `sleep` на 1–86400 секунд с причиной и следующим шагом. Инструмент отвечает сразу; мост останавливает генерацию модели и продолжает тот же разговор после ожидания. В чате видны время и счётчик пробуждения, есть **Продолжить сейчас**. Во время сна можно отправлять уточнения и отменять задачу.

Мост и целевая вкладка должны оставаться доступны. Автоматически запущенный мост живёт отдельно от терминала; выключенный компьютер не выполняет действия. Сон восстанавливается после перезапуска моста. Если браузер отключён, мост ждёт переподключения и не создаёт заново пользовательскую вкладку. Лимиты срока/активной работы/ходов сохраняются. Истёкшие разрешения сайтов надо подтвердить снова.

Ожидание само по себе не просматривает и не прослушивает видео: после него надо проверить фактическое воспроизведение, счётчик и состояние страницы. Сайт может приостанавливать видео в фоновой вкладке. Таймер возобновляет только управляемую задачу моста, а не посторонний разговор в настольном Codex.

## 6. Обновления

В настройках доступны **Только критические** (по умолчанию), **Только вручную**, **Все официальные**. Мост проверяет обновления при запуске и каждые шесть часов. В чате видны версии и отставание расширения; **Проверить** запускает новую проверку. Агент использует `browser_updates` → `check` / `apply` с той же политикой. Ручная установка доступна в настройках.

Критическим считается обновление, отмеченное автором в `update.json`, либо версия ниже указанной минимально поддерживаемой. Метаданные должны совпадать с версией package.json. Источник — только `main` официального репозитория; MCP не меняет источник и политику автоустановки.

Обновление откладывается до окончания активной или спящей задачи. Нужны чистая ветка `main` и fast-forward. Зависимости, синтаксис, тесты и сборка проверяются в отдельном Git worktree **до** изменения проекта. После установки расширение перезагружается, мост перезапускается. Ключ и локальная история сохраняются. При ошибке установки откатываются только собственные изменения обновления при всё ещё чистой рабочей копии; иначе сообщается commit для восстановления без перезаписи ваших правок.

Первое обновление со старой версии без этого механизма:

```bash
git pull --ff-only
npm ci
npm run setup
npm run package
```

Остановите старый мост, запустите обновлённый и перезагрузите расширение Chromium либо заново загрузите собранное дополнение Firefox. Подтвердите новые разрешения браузера, если он их запросит. Выполните doctor. При несовпадении версий не удаляйте `.local/connection.json`.

## Ручная настройка и ошибки

MCP сам запускает мост. `npm run bridge` нужен для работы в открытом терминале; второй мост на том же порту запускать не надо. `npm run status` показывает связь, `.local/bridge.log` содержит журнал.

Linux/macOS: найдите PID через `lsof -iTCP:17863 -sTCP:LISTEN`, затем `kill -TERM PID`. Для другого порта замените число. Windows PowerShell: найдите слушающий Node PID через `Get-NetTCPConnection -LocalPort 17863 -State Listen` и остановите этот процесс. Следующий запрос MCP запускает новую версию. Корректный перезапуск сохраняет запланированный сон; прерванные активные действия сами не повторяются.

Ручной пример с вашими абсолютными путями; в Windows TOML можно использовать прямые слеши:

```toml
[mcp_servers.browser_bridge]
command = "/absolute/path/to/node"
args = ["/absolute/path/to/project/server/mcp.js"]
startup_timeout_sec = 10
tool_timeout_sec = 900
required = true
# По желанию, только для явно делегированных действий:
# default_tools_approval_mode = "approve"

[mcp_servers.browser_bridge.env]
BROWSER_BRIDGE_CONFIG = "/absolute/path/to/project/.local/connection.json"
```

Точка входа stdio MCP — **server/mcp.js**, не server/daemon.js. Настройки соответствуют [официальной документации Codex](https://learn.chatgpt.com/docs/config-file/config-reference).

| Ошибка | Решение |
| --- | --- |
| Нет browser_* | Проверьте регистрацию и перезагрузите MCP/начните новую сессию. |
| Расширение не подключено | Проверьте мост, импортируйте его файл, отключите другой браузер. |
| URL constructor / служебная страница | Обновитесь до 0.5.0 и выберите сам HTTP(S)-сайт в чате. |
| Версии различаются | Перезапустите мост, перезагрузите расширение; Firefox сначала пересоберите. |
| Нет разрешения сетевой защиты | Перезагрузите дополнение и подтвердите разрешения браузера. |
| Codex требует подтверждения инструмента | Разрешите его в Codex или явно включите делегирование выше. |
| Ожидается доступ к сайту / JavaScript | Решите в интерфейсе расширения; подтверждение Codex не заменяет это разрешение. |
| Обновление отказывается из-за изменений / divergence | Сохраните правки и согласуйте main; updater их не удалит. |
| Cannot attach | Закройте DevTools; не закрывайте браузерное уведомление debugger. |
| Команда недоступна в Firefox | Используйте DOM-команды; native input/CDP/upload/dialog/console/network не поддерживаются. |

Если браузер на другом компьютере, настройте SSH-туннель к мосту, безопасно передайте файл подключения и установите расширение там. Обновление исходников на компьютере Codex не меняет файлы на отдельной машине браузера: передайте новый архив и перезагрузите дополнение там. Пути upload относятся к машине браузера. Файл подключения нельзя публиковать или коммитить.
